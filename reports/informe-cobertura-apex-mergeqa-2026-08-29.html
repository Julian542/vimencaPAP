3. Estrategia aplicada

  1. Retrieve preventivo: se recuperó la versión vigente de cada clase y test antes de modificar, evitando sobrescribir cambios de MergeQA con versiones antiguas.
  2. Diagnóstico por clase: se ejecutaron tests de forma agrupada y controlada, revisando fallos y líneas no cubiertas.
  3. Casos simples y efectivos: se priorizaron retornos tempranos, validaciones, caminos de error y helpers @TestVisible.
  4. Control de asíncronos: se evitó crear cadenas reales de queueables. Cuando fue necesario cubrir una continuación, se utilizó un ID inexistente controlado para que la cadena terminara inmediatamente.
  5. Despliegues incrementales: se desplegaron solo los tests afectados y la adaptación de soporte requerida.
  6. Validación consolidada: al finalizar se repitieron las 13 clases test del alcance en un único job y se consultó la cobertura agregada de las 14 clases productivas.
